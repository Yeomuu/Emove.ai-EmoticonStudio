디자인 가이드는 제외한다. 아래 섹션들은 각 Notion 하위 문서의 끝에 추가할 업데이트 원문이다.

## EMOVE PRD

### 2026-06-29 구현 기준 업데이트

- EMOVE는 사용자의 카메라·음성 입력을 하나의 감정으로 합치는 서비스가 아니라, 행동·표정·음성·텍스트·감정 효과를 분리해 이모티콘으로 합성하는 서비스로 확정한다.
- 입력 완료 후 자동 생성 범위는 캐릭터 행동 프레임 5장으로 제한한다.
- 코어 이펙트 이미지는 비용 제어를 위해 Edit 화면에서 사용자가 `코어 이펙트 생성` 버튼을 눌렀을 때만 생성한다.
- 사용자가 감정을 수동 변경해도 이미 입력된 표정, 행동, 목소리, 말풍선 문구는 덮어쓰지 않는다.
- 수동 감정 선택은 배경 이펙트와 코어 이펙트에만 사용한다.
- 생성 대기 중에는 현재 단계가 보이도록 `입력 데이터 저장 중`, `캐릭터 행동 프레임 5장 생성 중`, `편집 캔버스 준비 중` 상태를 표시한다.
- Library는 전체, 이모티콘, 캐릭터 보기를 분리한다.
- 그룹 필터와 검색은 라이브러리 탐색 흐름의 핵심 기능으로 유지한다.
- 현재 UI는 제공된 화면 기준 자료를 따르며, 추후 새 화면 명세가 제공되면 해당 세트를 최신 화면 기준으로 삼아 교체할 수 있다.

## EMOVE 기술 명세서

### 2026-06-29 구현 기준 업데이트

- 구현 스택은 Preact, TypeScript, Vite, Signals, native CSS tokens로 유지한다.
- Firebase는 Web modular SDK를 사용한다.
- Firestore는 실시간 구독이 필요하지 않은 저장 흐름에 맞춰 `firebase/firestore/lite`를 사용한다.
- Firebase Storage 경로는 `emoticons/{ownerId}/{projectId}.gif`로 사용한다.
- Firestore 컬렉션은 `characters`, `captures`, `projects`, `stickers`를 사용한다.
- 원본 카메라 Blob, 원본 오디오 Blob, 대형 data URL, 생성된 코어 이펙트 data URL은 Firestore에 저장하지 않는다.
- Analytics는 `measurementId`가 있고 브라우저에서 지원될 때만 lazy 초기화한다.
- OpenAI API key는 브라우저에 노출하지 않고 Vite dev server의 `/api/openai/*` 프록시에서만 사용한다.
- 프롬프트 생성과 정제는 `OPENAI_PROMPT_MODEL`로 분리한다.
- 이미지 생성 모델은 `gpt-image-2`를 유지한다.
- `OPENAI_IMAGE_CONCURRENCY=2`로 프레임 생성 병렬성을 제한해 같은 이미지 호출 수에서 체감 대기 시간을 줄인다.
- 캐릭터 생성, 행동 프레임 생성, 코어 이펙트 생성을 서로 다른 프롬프트 계약으로 분리한다.
- 캐릭터와 이펙트 이미지는 flat chroma-key green 배경으로 생성하고, 브라우저에서 투명 PNG data URL로 변환한다.
- GIF export와 loop preview는 같은 renderer 경로를 공유한다.
- QR 코드, Firebase, Analytics는 필요한 순간에만 lazy load한다.
- 미사용 PNG와 legacy asset/source 폴더를 제거하고, 사용 에셋은 `src/assets` 아래에서 참조한다.

## EMOVE 이론적 배경

### 2026-06-29 구현 기준 업데이트

- 사용자의 감정 표현은 하나의 감정 라벨로 환원하기 어렵다.
- 같은 입력 안에서도 웃는 표정, 낮은 음량, 슬픈 감정 선택, 밝은 발화가 동시에 존재할 수 있다.
- 따라서 EMOVE는 행동, 표정, 음성, 발화, 사용자가 선택한 감정 효과를 분리해 기록한다.
- AI는 사용자의 진짜 감정을 확정하는 판정자가 아니라, 편집 가능한 생성 초안을 만드는 보조 도구로 사용한다.
- 사용자가 감정을 수동 변경해도 표정·행동·음성·텍스트를 덮어쓰지 않는 이유는 사용자 표현 통제권을 유지하기 위해서다.
- 캐릭터 프레임, 배경 이펙트, 부가 이펙트, 텍스트를 레이어로 분리하면 재편집성, 반복 사용성, 오류 수정 가능성이 높아진다.
- 캐릭터 토큰에 2D/3D `styleMode`를 명시하는 것은 생성 프레임 사이의 스타일 혼합을 줄이고 캐릭터 정체성을 유지하기 위한 장치다.
- GIF와 editor preview가 같은 renderer를 공유하도록 한 것은 제작 중 예측한 결과와 최종 export 결과의 차이를 줄이기 위한 설계다.

## EMOVE 서비스 고도화 리서치

### 2026-06-29 구현 기준 업데이트

- 사용자는 생성 중 피드백이 없으면 서비스가 멈춘 것으로 느낄 수 있다.
- 생성 대기 UX는 단계 상태를 직접 보여주는 방식으로 개선한다.
- 현재 단계 표시는 `입력 데이터 저장 중`, `캐릭터 행동 프레임 5장 생성 중`, `편집 캔버스 준비 중`으로 구성한다.
- 비용 절약을 위해 입력 완료 시 코어 이펙트 이미지는 자동 생성하지 않는다.
- 기본 사용 흐름에서는 Canvas 기반 로컬 이펙트로 즉시 미리보기를 제공한다.
- 고품질 생성형 코어 이펙트는 사용자가 필요하다고 판단할 때만 Edit 화면에서 생성한다.
- Firebase, Analytics, QR 코드, 화면별 bundle은 필요 시점에 lazy load한다.
- Firestore Lite 전환으로 DB 관련 chunk를 줄였다.
- WebP 중심 에셋 사용과 미사용 PNG 제거로 프로젝트 용량과 로딩 부담을 줄였다.
- Edit 화면의 loop preview는 실제 GIF가 아니어도 같은 5프레임과 frame delay를 사용해 사용자가 export 전 움직임을 확인하게 한다.

## EMOVE 하이브리드 입력·포즈 리타게팅 기술 설계

### 2026-06-29 구현 기준 업데이트

- 카메라 입력은 상반신 행동, 제스처, 포즈 요약에 사용한다.
- 음성 입력은 발화 텍스트, 음량, 감정 추론에 사용한다.
- 입력 분석에서 얻은 표정, 행동, 음성 텍스트는 사용자가 감정을 바꿔도 덮어쓰지 않는다.
- 캐릭터 행동은 5개 프레임으로 생성한다.
- 각 프레임의 캐릭터 행동은 달라질 수 있지만, 사용자가 편집한 레이어 위치, 크기, 회전은 이후 프레임에 유지되도록 한다.
- Edit 타임라인은 배경 이펙트, 캐릭터, 부가 이펙트, 텍스트의 4개 레이어로 고정한다.
- 코어 이펙트는 생성형 자산 또는 로컬 Canvas 효과로 처리한다.
- 부가 이펙트는 고정 파츠로 유지한다.
- GIF export와 editor preview는 같은 합성 renderer를 사용해 색상, 알파, 레이어 위치 차이를 줄인다.
- 텍스트 레이어의 선택 박스는 실제 렌더링된 말풍선 측정값과 같은 기준을 사용해 크기 조절과 회전 중심 어긋남을 줄인다.
